# Process Card Payouts

Now that you have completed the [Collect Cards](/guides/payment-methods/collect-cards) guide, let's process a card payout with the newly captured card.

## Getting Started

<GettingStartedSection />

### Get your Secret Key

Next you will need your `Secret Key`. [Go to your Developers section](https://portal.publicsquare.com/developers/api-keys) and click `Reveal` for your `Secret Key` and copy the value.

<Alert>Save the Secret Key as it will be used in the next steps of this guide.</Alert>

## Card Payout Requirements

A card payout pushes funds straight to the cardholder's card. Three conditions must be met before a card payout succeeds.

**Your account is onboarded for card payouts.** If card payouts are not enabled yet, the request is rejected:

```shell showLineNumbers title="Account not onboarded"
{
  "title": "Error",
  "status": 400,
  "detail": "account has not finished onboarding for payouts."
}
```

**Your holding account holds enough funds.** Card payouts are funded from your holding account balance, not from an incoming payment. Check the balance with the [Get holding account balance](/api/accounts/get-holding-account-balance-by-id) endpoint. Two failures are possible:

```shell showLineNumbers title="Holding account problems"
{
  "title": "Error",
  "status": 400,
  "detail": "holding account does not have sufficient funds"
}
```

```shell showLineNumbers title="No holding account"
{
  "title": "Error",
  "status": 400,
  "detail": "account does not have a holding account associated with it."
}
```

**The card can receive a push payment.** Not every card supports payouts. Cards that support fast funds receive the money within minutes. Cards that support only standard push settle more slowly. Cards that do not support push payments at all are rejected:

```shell showLineNumbers title="Card does not support payouts"
{
  "title": "Error",
  "status": 400,
  "detail": "payment method does not support payouts"
}
```

<Alert>Payouts accept a `card` or a `bank_account` payment method. Apple Pay and Google Pay tokens cannot receive a payout.</Alert>

## Process the Payout

We will need to use the information from the previously collected card to create a new payout.

For example, given you have a previously collected card:

```json showLineNumbers title=card.json
{
  // highlight-next-line
  "id": "card_AjkCFKAYiTsjghXWMzoXFPMxj",
  "account_id": "acc_B518niGwGYKzig6vtrRVZGGGV",
  "environment": "test",
  "cardholder_name": "John Smith",
  "last4": "4242",
  "exp_month": "12",
  "exp_year": "2025",
  "fingerprint": "CC2XvyoohnqecEq4r3FtXv6MdCx4TbaW1UUTdCCN5MNL",
  "created_at": "2024-06-30T01:02:29.212Z",
  "modified_at": "2024-06-30T01:02:29.212Z"
}
```

### Create a Payout

We need to make a call to [Create Payout](/api/financial/create-payout) endpoint:

```shell showLineNumbers title="Create a Payout"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPONTENCY-KEY: '09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"
  },
  "customer": {
    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@email.com"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

<Alert>The amount is provided in cents. 1000 is the equivalent of $10.00</Alert>

<Alert type="warning">The IDEMPONTENCY-KEY header can be passed to protect against duplicate payouts being processed.</Alert>

<Alert>
  Card payouts are always pushed directly to the card, so the `payout_type` field does not apply. It only affects bank account payouts — see
  [Payout Types](/guides/payouts/process-ach-payouts#payout-types).
</Alert>

### Create with Existing Customer

If you [created a customer](/api/accounts/create-customer), then you can pass the `customer_id` when processing the payout:

```shell showLineNumbers title="Create a Payout with Customer"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPONTENCY-KEY: '09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"
  },
  "customer": {
    "customer_id": "cus_7Ay5mcUXAxwrN6wQEQUVEHBCJ"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

### Create with Customer's Payment Method

If you [attached the card to a customer](/api/financial/attach-card-to-customer), then you can omit the `customer` section when processing the payout:

```shell showLineNumbers title="Create a Payout with Payment Method"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPONTENCY-KEY: '09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"
  },
  "billing_details": {
    "address_line_1": "111 Test St.",
    "city": "Des Moines",
    "state": "IA",
    "postal_code": "51111",
    "country": "US"
  }
}'
```

### Create with Payment Method's Billing Details

If you supplied the `billing_details` or [updated the card](/api/financial/update-card), then you can omit the `billing_details` section when processing the payout:

```shell showLineNumbers title="Create a Payout with Payment Method"
curl 'https://api.publicsquare.com/payouts' \
-X 'POST' \
-H 'X-API-KEY: <SECRET_API_KEY>' \
-H 'IDEMPONTENCY-KEY: '09ec2c87-7fb8-44ca-bb18-5c71a76974da' \
-H 'Content-Type: application/json' \
-d '{
  "amount": 1000,
  "currency": "USD",
  "payment_method": {
    "card": "card_AjkCFKAYiTsjghXWMzoXFPMxj"
  }
}'
```

The `processor` field shows which processor sent the payout. Your account configuration decides this value.

A card payout does not always finish in one request. The payout can return `pending` and reach `succeeded` later, or reach `declined` if the card network rejects it. Subscribe to
[webhooks](/concepts/webhooks) for the final status instead of assuming the create response is terminal.
